# 色彩库与角色分配

此文是旧版拼版四色卡的记录。新增高清集优先使用 [finished-palette-guide.md](finished-palette-guide.md) 及其角色色板；旧编号与 HD 编号独立，不能按同号对应。

## 三种颜色数据

- `palette-library.json`：100 组 × 4 个图示 HEX，共 400 个色卡项，389 个去重后的文字色值，来自原图印出的标签。
- `sampled_swatch_hex`：记录的色块采样框中出现最多的解码 RGB，避开边框与过渡边缘，用于核对截图实际色块，不冒称作者源文件颜色。
- `extract_palette.py`：对头像裁切做完整 RGB 直方图和 24 色量化，包含压缩、抗锯齿色，不替代图示色卡。全量产物在本项目 `outputs/avatar-reference-analysis/pixel-colors/`；正常运行 Skill 无需读这些直方图。

400 个色卡项不是 400 种唯一颜色，也不是作品只含 389 种 RGB。不能把所有头像混合量化成一套全局色板。

## 原图标签与色块的差异

保留文字与采样两个字段，不默默改写来源：

- 059 的首个图示标签为 `#911D22`，实际色块为更亮的橙棕，以 JSON 采样值为准。
- 095 的第二、三个标签写 `#FFEE00`、`#FF50A3`，实际色块分别为粉色、青色；头像衣服也是青色。视觉复现查看 `assets/portraits/095.png` 并优先用采样色。

其他色卡小幅 RGB 差异可能来自截图/图像处理，不能直接断言源文件错误。

## 选色规则

1. 先选一整组配色关系，再分配背景、主线、肤/发、衣服、点缀，不随机抽四个高饱和色。
2. 四色没有固定角色顺序。024 是背景/肤色/深衣线/黄发；016 是黄衣/紫底/粉肤/深紫发线。不能把第一色统一当肤色。
3. 默认保留照片可见肤色、头发深浅与主色类别，将色板重点用于背景、衣服、轮廓、圆腮红。用户要求整幅艺术重配色时，再让脸/发进入粉紫、绿、蓝等色域。
4. 四色只是主色提纲，允许腮红、自然肤色与必要暗面作为补色，不为凑四色删辨识信息。
5. 发型与背景要分开，眉眼在面部上清楚。强调色可放在腮红、发梢、领口、耳饰或细衣边，避免处处发光。
6. 换色不换形：金发、眼镜、胡须、口罩、项链和衣服符号不能随色卡自动迁移到照片人物。

## 已分配角色的制作方案

其他方案查看 `reference-index.md` 并打开对应裁切图分配角色，不靠色值排序自动推断语义。四色清单也不能解释全部画面颜色。

提示词应写“角色 + 色值 + 面积关系”，例如：“青绿背景 #01CBAD，主轮廓深绿 #004D42，保留照片自然肤色，珊瑚圆腮红；衣服大面积深绿，黄色 #FEDB24 只作领口小点缀。”

HEX 是生成方向，模型未必逐像素匹配。严格品牌色需在最终编辑中校准，不能仅凭提示词宣称色值完全一致。
