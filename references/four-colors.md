# 一张底稿，同几何四配色

默认一次生成`semantic-props-v3`区域编码底稿，再在本地解码角色ID与线条alpha，为四版分别填入一套完整TS配色。四版五官、轮廓、发型、姿态、线条位置与粗细完全共用；线色可随各版模板变化。`--variants 1`保留同样的一次底稿单图路线。不是分别调用模型画四个人物，也不交付技术编码色。

## 配色与结构

每版来自[source-colorways.json](source-colorways.json)的一套当前模板，肤面、肤影、背景、头发、衣服、腮红、细节、主线和渐变同源。默认从70套不放回随机，批内不重、相邻批排除、整轮用尽再开，详见[source-colors.md](source-colors.md)。显式四套可用`--colorway-references 25 55 16 47`；单图用`--colorway-reference 55`。不跨模板取色、不计算新色、不强迫肤色或背景互异。

服装外套/内搭、领袖、花纹、配饰和帽饰独立；衣褶只画细线，单件纯色衣服不强制第二填色。道具主面/不同材料次面和舌头独立，局部可复用本套已允许色值；冰淇淋与甜筒分色，舌面不能用墨色。见[服饰](garment-design-guide.md)和[道具](object-details.md)。

人物渐变只应用所选模板已记录的同角色端点和方向；无记录则平涂。实际可见区域的端点、过渡和色差须在原尺寸与128像素下可读；同套同角色有已记录替代项可本地重映射，无合用项则停止。不能跨角色搬渐变、在皮肤/背景铺渐变，不能用硬切两块色、抗锯齿或细边冒充。TS-070背景渐变仅存档，输出用该套采样单色。

每格衣服/身体必须连续到最后一行。允许解码后按共同蒙版统一向下平移并保存位移记录；不缩放、不拉伸、不复制底行、不贴水平色带。整体留白与完整肢体仍需实际检查，技术贴底不证明结构合理。

## 输出与尺寸

默认每版1024×1024，四图2×2拼为2048×2048。独立文件位于`variants/variant-01.png`至`variant-04.png`，拼图为`variants/avatar-four-colors.png`；交付以`result.json.delivery`与`variant_files`实际返回为准。`variants`为数量，不能当文件列表。保存底稿、`role-ids.png`、`line-alpha.png`、角色mask、计划和处理记录。

编码底稿须不透明；四图透明底稿拒绝，不靠合白底绕过分区要求。足够大的非方形底稿可等比缩小适配技术白色方形底、底部对齐后解码，不裁切、不拉伸、不放大。技术白底与区域编码色都须转换为各版最终颜色，不留白边或拼缝。实际PNG尺寸与视觉构图分别检查。

仅有一次模型请求不代表单图与四图耗时完全相同；本地解码、填色和保存计入实际耗时。失败、超时或状态不明时查原请求，不自动重复提交，不另画四张兜底。

## 选版与高清

版号按左上、右上、左下、右下为1–4。只选某版时直接展示已有单图，不生图。明确要求高清后：

```bash
python3 "<skill-dir>/scripts/run_avatar.py"   --brief "<preview-output>/brief.json" --select-variant 2 --stage final   --approved-preview "<第2版单图绝对路径>"
```

final冻结完整TS来源与角色计划，默认high，仍只生成一张底稿；它不承诺与低质量preview逐像素同线。需要逐像素保留时只复用已有蒙版本地渲染，不称重新生成高清。四版一起高清使用`--variants 4`并批准一张单图，不能上传拼图作为一名人物。

## 仅本地重填

```bash
python3 "<skill-dir>/scripts/recolor_avatar.py"   --master "<已适配的编码底稿绝对路径>"   --request "<request/generation-request.json>"   --out-dir "<新的输出目录>"
```

命令不调用模型、不负责方形适配；保持来源与角色验证，不能用库外HEX或跨模板方案绕过。保留旧输出与原底稿。像素验证可证明同批几何和颜色，不证明照片辨识度、人体、嘴型或画风，交付前实际对照一次。
