# 同线稿四配色

默认 CLI 输出四配色；`--variants 1` 输出单图 `avatar.png`，用 `--colorway-reference 55` 选择整套原作。单图、四配色及选版高清均一次向全局 gen-img 提交照片和造型参考，获得一张区域编码底稿，再用本地 Pillow 解码线条与角色蒙版并精确填色。单图一套完整原作方案，四配色填入四张对应原作的完整配色并拼成2×2；不会分别重画四个人物或逐张调用生图。

## 底稿、颜色与几何

纯黑白线稿不能自动说明每个封闭区域属于皮肤、头发还是衣服，因此中间底稿使用固定技术色标记区域。它们只是程序读取的区域ID，不是成品肤色、背景或线色，不得直接当头像交付。底稿不画渐变、纸纹、柔光或写实阴影；实际可见的人物特征、神态、手势、纹身和配饰仍需保留，不能用技术分区简化掉用户要求。

本地只解码一次，四版共用同一套角色ID与线条透明度蒙版。线条位置、粗细、五官、发型轮廓和姿态不会因换色重新生成；线条几何不动，线色则随各版对应原作的整套方案变化。固定蒙版只能保证本批换色的几何一致，不能证明底稿已经保留了照片人物特点，仍需一次照片对照。

四个 `variant_plans` 执行 `single-source-colorways-v1`，每版对应[整套原作配色目录](source-colorways.json)中的一张入库原作，保存其来源编号、原图路径、完整角色色与渐变。肤面、肤影、背景、头发、衣服、腮红、细节、主线色和渐变端点均取自同一 `source_hd_id` 的正确部位采样，保持这张原作的配色关系。默认选四张已视觉核对且背景亮度≥150/255的完整原作方案；可用 `--colorway-references 25 55 16 47` 显式指定目录内的四张原作；不跨图找肤色或背景，不从艺术色组拼发衣，不计算新色，也不以颜色距离最大化来凑区别。肤色和背景允许重复，整体配色关系优先。不能用全图滤镜替代区域换色。构图沿用composition.py的留白胸像目标：头高40%–48%、顶空12%–16%、下巴55%–64%，肩宽65%–80%，两侧留白并保留颈、肩与上胸；这些是设计目标，不是原作统计。最终每版在普通头像显示尺寸下都必须能看清至少一处二色连续渐变：两端颜色有可辨面积，中间平滑过渡，保留原作完整端色和方向。头发只是一个位置，衣服或编码为衣服角色的服饰色块也可使用其自身的原作渐变；同一原作多个已采样部位可见时一并保留。只在可见色块分布中映射，不让被遮挡区域、孤立误标像素或极端边缘撑大范围、把渐变压成近似纯色。若区域不可见或两端覆盖不足，只能使用同一原作已采样的同角色 `gradient_options` 本地重映射；没有合用选项则停止说明。不能把原作头发端点搬到衣服，更不能转移到皮肤或背景。单图同样沿用整套原作与同一可见性检查，不独立配发衣、线色或渐变。

旧混搭brief在单图和四配色均自动迁移至完整同源方案并记录原因。已记录的旧同源渐变按 `visible-source-gradients-v2` 补齐原作完整端色，保留原作编号及其余角色色；仅迁移与已知旧目录精确一致的计划，篡改色或来源不符仍拒绝，当前合规冻结方案精确复用。 普通出图只读维护好的目录，不每次扫描、分析69张原图。全部路线检查最终可见RGB的端点覆盖、过渡面积和颜色跨度，并以128×128缩略图再核对渐变未消失；很多插值步数不代表肉眼可见，微弱同色变化、细边亮线、硬切两块色、抗锯齿和噪点不能通过。像素指标不理解角色语义，实际效果仍在同一次快速看图中核对。

单图与四配色均仅支持 `expressive`。保留照片发色会拆散完整同源方案；新请求或旧brief使用natural时停止说明，不通过切到单图绕过。

## 输出与计时

原底稿与共用蒙版、四套计划和处理记录均保存。默认请求1024×1024正方形留白胸像。每张独立PNG为1024×1024，2×2拼图为2048×2048，不把四张压缩进一张1024画布。明确指定其他方形尺寸时，每版按该尺寸交付，拼图宽高各为单版两倍。执行器将这些文件保存在 `variants/`：`avatar-four-colors.png` 为拼图，`variant-01.png` 至 `variant-04.png` 为四张单图，同时保存 `role-ids.png`、`line-alpha.png`、各角色mask和 `mask-manifest.json`。默认展示路径读取 `result.json.delivery`，单图路径读取其 `variant_files`（`variants` 为数量4），不要沿用旧模式的固定 `avatar.png` 路径。编码原底稿必须不透明；透明底稿先拒绝，不能靠白底合成绕过解码要求。square下必要时将足够大的原图等比缩小、适配至白色编码方形底并底边对齐，再解码并填入各版库内颜色；保留全图，不裁切、不拉伸、不放大，不追加模型请求。小于目标且需放大时停止。保存原底稿与实际适配操作。

仍只有一次图片API，但本地解码、换色和保存属于新增工作。按实际记录报告模型与本地处理耗时，不承诺与单图耗时相同，也不把脚本计时当作照片收到至展示的端到端耗时。模型颜色未遵守编码或解码不可靠时保留记录并停止；不自动重试、不交付编码色、不偷偷另画四张。

## 选择某一版与高清

只说“选第2版”时，直接展示 `result.json` 中对应的已有单图，不发新请求。编号按拼图左上、右上、左下、右下依次为1–4。

明确要求某一版高清后，传入对应单图，不能把四宫格当作一名人物的预览：

```bash
python3 "<skill-dir>/scripts/run_avatar.py" \
  --brief "<preview-output>/brief.json" --select-variant 2 --stage final \
  --approved-preview "<第2版单图的绝对路径>"
```

选版以 `source_colorway_id` 冻结该版对应原作的整套配色与线色，不重新抽配色；旧 `art_palette` 和单图随机肤色/背景规则不能覆盖。需要四个一起高清时仍使用 `--variants 4`；批准预览选择其中一张单图。final按既有规则用high质量重新生成，每版仍为1024×1024、四配色拼图2048×2048；新的四版内部共用同一蒙版，但不承诺final与低质量preview逐像素同线；若必须逐像素保持原底稿，复用蒙版本地重填，不调用final，也不称为重新生成高清。

## 仅本地重填

已有编码底稿和请求文件时，在同一 skill 内复用其结构重新渲染四套计划：

```bash
python3 "<skill-dir>/scripts/recolor_avatar.py" \
  --master "<已适配为1024×1024的编码底稿绝对路径>" \
  --request "<request/generation-request.json>" \
  --out-dir "<新的输出目录>"
```

此命令只在本地读取底稿和 `variant_plans`，不调用图片模型，也不负责square适配。渐变重映射与检查仅在本地执行，不增加模型调用；旧版精确同源计划先按渐变策略升级并记录，非法或篡改计划仍停止，不以失败为由自动付费重试。使用执行器保存的 `master.png`；若没有适配文件且原底稿已为1024×1024，可直接使用原底稿。不得将旧native长方形直接重填后称作默认正方形交付。使用新输出目录保留旧结果；库外色、深色背景或跨原作拼接不得通过本地重填绕过完整同源规则；不同版本使用不同原作线色不属于几何变化。
