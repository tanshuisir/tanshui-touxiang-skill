# 当前70套完整配色与随机历史

单图、四配色、预览与高清统一采用`single-source-colorways-v1`。当前TS-001–TS-070每张对应一套独立完整方案，见[逐图索引](colorway-index.md)，运行入口为[source-colorways.json](source-colorways.json)。全部70套参与，不按背景明度、白色系或有无人物渐变筛选；白色/近白背景允许，成品背景仍须满幅、不透明、单一采样纯色。

每版肤面、肤影、背景、头发、衣服、腮红、细节、主线及人物渐变绑定同一套当前模板。`source_hd_id`为兼容字段名，在本发布仅代表当前TS编号。照片决定人物结构、神态、衣型与配饰，不锁照片原色。不得跨模板拼肤色或换背景，也不得为求每版肤色互异而造色。

角色取样保留当前PNG路径、SHA-256、1000×1000坐标与精确HEX；缺失角色有明确同套回退/适配说明，不能把适配说成原图已有部位。整图额外高频色未经角色确认不能拿来补色。维护标注为[template-annotations.json](template-annotations.json)，角色派生数据见[source-role-colors.json](source-role-colors.json)；普通出图只读缓存目录，不重复扫描70张图。

肤面为平涂，肤影为合理硬边结构面，不新增肤面渐变或高光。模板无已记录人物渐变则保持平涂；有渐变则沿用同角色端点、方向和连续过渡，并核对最终RGB及128像素下的可见性。区域受遮挡时只可选择同套同角色已记录的`gradient_options`，无合用选项则停止，不造新端点、不跨角色搬色。TS-070的背景渐变只作元数据存档，成品使用其已采样的单色背景，不生成渐变底。

维护时从当前模板重建：

```bash
python3 scripts/build_template_library.py --source-dir assets/templates --skill-dir . --annotations references/template-annotations.json
```

更新后须重新核对图片、取样点与角色，不只运行脚本。

## 随机与避重复

选择策略`whole-library-no-replacement-v3`：

- 新四配色随机抽四套不同来源，下一版排除上一版所有来源；调换顺序仍属重复。单图和四图共用逐套不放回轮次，70套逐一使用后才开新轮。
- 70不能被4整除。某批取完旧轮尾部后从新轮补齐，补齐仍排除上一批及本批已取来源；不丢尾板、不提前重复，单/四图切换同样执行。
- 橙/珊瑚背景（HSV饱和度≥0.12，色相5°≤h<50°）及绿/青绿（65°≤h≤190°）基础权重0.35，其余1；近3批每次出现再乘0.6，累计用量轻微降权。权重只影响尚未使用候选的顺序，不能突破硬排除；整轮每套仍各一次，不能声称整轮橙绿总量减少。
- 不重复按整套来源编号判断。不同模板可能具有相同背景HEX、肤色或相似色相，不能承诺所有像素颜色永不重用；不能拆色板强行避免共享单色。有限库用尽后允许新轮复用，相邻批依然不重叠。

SQLite默认路径为`$CODEX_HOME/state/tanshui-touxiang-skill/template70-colorway-history.sqlite3`，未设置时为`~/.codex/state/tanshui-touxiang-skill/template70-colorway-history.sqlite3`。新库使用独立账本，不迁移先前素材库历史；跨项目和进程保存。`TANSHUI_AVATAR_COLOR_HISTORY`可显式指定其他持久历史或隔离测试。事务锁覆盖抽取与预留，防止并发穿透。损坏或不可读写即停止，不清空、不回退固定方案。准备阶段即预留，失败任务也消耗本次抽取。请求记录候选数量、抽取来源、前批硬排除、轮次与跨轮明细。

选版、故障续交付、明确修图及已确认高清复用冻结方案，不再消耗新随机记录。新独立版本或明确重新配色使用`--random-colors`。用户明确指定整套编号时可以覆盖随机选择，示例编号不得变成默认；显式选择不自动改写随机历史。

每阶段仅一次模型请求，颜色在本地蒙版重填。输出中技术色残留、区域误标、无效透明底稿或明显画面错误必须指出并停止，不能为测试抽色追加生图。来源和像素校验不证明照片辨识度、结构、嘴形或画风，仍需实际看图。
