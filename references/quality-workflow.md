# 人物特征、自检与有限修订（显式请求的review模式）

**仅当本次用户要求逐项自检、对照检查或检查并修正时读取并执行。** 在brief设置 `workflow: "review"`，才使用详细提示词与最多一轮修订预算。普通照片转换默认fast，照片直传生图模型；完成后一次批量查看原照、实际成品和风格参考，核对人物特征、统一眼睛、普通头像尺寸下清晰的主体渐变和纯色对比底后交付，不运行本文件的详细步骤，也不自动追加调用。旧版默认自检授权不延续到fast模式。

`stage` 与 `workflow` 独立：默认preview、quality low；用户通过对话明确确认预览并要求高清后，另行以final、quality high生成。两阶段默认请求一张1024×1024正方形留白胸像；四配色本地输出四张同尺寸单图及2048×2048拼图。用户一开始明确要求直接高清时可直接final。自检通过只表示本阶段通过，不代替用户确认，也不自动触发高清；用户只提出修改时保持预览。

默认仍为四配色；单图、四配色及选版高清都只生成一次编码底稿，再经本地角色蒙版精确填入最终肤面/肤影、非白背景等角色色及人物渐变。单图一套方案，四配色四套，不增加生图次数或全库分析；四版共用同一角色ID和线条透明度蒙版，几何固定；各版颜色与线色按 `single-source-colorways-v1` 对应一张完整原作，成品渐变与角色色在本地填入。线色可随对应原作变化，不把不同线色误判为线稿几何变化。编码底稿本身不受成品颜色/渐变检查，而是检查区域编码与不透明要求。

review模式保持本次高清参考、平顺线条、五官符号、艺术配色、必需局部渐变、腮红、阴影和交付规范，增加能追溯的自检。全局gen-img仍负责凭据、模型过滤与生图；本Skill仅在明确请求此模式时做画面对照。

## 1. 先把照片事实转成可核对的绘画决定

照片直传模式的identity_source为photo，review_spec.plan_source为photo_requirements。identity_plan中的requirement、render_as、emphasis和do_not_change是生图要求，不含photo_evidence，也不能冒称主模型已观察。详细自检时须实际看原照、成品与风格图，再填写可见对照；生成模型直接提取特征不等于该项已通过。以下手写观察与计划适用于已实际观察、主动采用详细特征路线的任务，不是普通fast的调用前置。

实际看照片，选择 3–5 项最有辨识力的可见特征。优先覆盖脸型/下颌、眉眼关系或鼻口关系中的可见信息，再结合发型、表情和关键配饰；不能只列“金发、黑衣服、耳环”之类通用标签。被遮挡、过曝或模糊的信息标为不可判断，不猜补；可辨识范围不足时说明限制。

照片只决定结构与神态：脸型、五官关系、发型剪影、衣型和配饰形状需要保留；四配色每版的肤色、肤影、背景、发衣、腮红、细节、线色和渐变来自source-colorways.json中同一原作，不锁定照片颜色。单图也使用同一原作完整方案，不独立选肤色、背景、线色或渐变；详见 [source-colors.md](source-colors.md)。记录颜色事实时不能让它变成未经用户要求的保色约束。每项分成：照片证据、画成什么、是否加强、不可改变什么。它是相对于这张照片的转译，不是识别人名、推断身份或检索相似人物。例：

```json
{
  "feature_index": 1,
  "photo_evidence": "正面照片里两颊饱满，下颌宽、下巴圆",
  "render_as": "用连续圆弧保留面颊体积和圆下巴，略加强饱满感",
  "emphasis": "emphasize",
  "do_not_change": "不削成尖脸，不缩窄下颌，不把成人画幼态"
}
```

`identity_plan` 覆盖 `identity_features` 的每一项，`feature_index` 从1开始。`emphasis` 只能是 `preserve` 或 `emphasize`，最多两项加强，其余保持。新任务填写明确计划；旧 brief 仍可构建，脚本将已有特征逐项带入，不凭空新增观察。旧 brief 的 `stylization` 在不冲突于当前硬约束时继续生效；调用前须核对它与逐项计划一致，旧眼部细节要求不覆盖统一眼睛画法。

允许把已有差异画得更清楚：发型更有节奏、圆脸更圆、原有头倾略强、镜框更醒目。禁止将特征反向改造，或同时放大所有五官。眼睛统一用短上眼睑连接向下的单色实心椭圆或圆角楔形，沿用库内选定主线色；不画包围眼白的杏仁形外框、眼白、独立虹膜/瞳孔层、反光点或镂空高光、睫毛及细致下眼睑。照片只决定眼距、眼宽、上眼睑倾斜与开合、视线和左右差异，并保留与眉毛的关系；闭眼/笑眼可用短弧线，不强行把所有人画成困倦半睁眼。不能为了“像本人”恢复照片的眼白、虹膜与反光，或统一成同样的眼距、开合和神态。此眼睛画法适用于全部模式、fast/review与预览/高清；旧brief、特征转译、所选参考或已确认旧预览含写实眼部细节时，以本规则重画眼睛，其余已认可内容继续保留。

## 2. 调用前核对

检查本次 brief、提示词、`generation-request.json` 三者：

- 每项主特征都有绘画处理，表情含义、视线和头肩关系一致；`stylization` 与逐项保留边界不冲突。
- 第一张只决定人物辨识结构、神态、衣型和配饰形状；第二张提供绘画语言，成品颜色以每版完整原作方案或本次单图计划为准，不迁移其脸、发型、衣型、配饰或姿势模板。肤色/肤影与背景必须跟本次原作模板，发衣色不必跟照片。经预览升级final时，以 `--approved-preview` 添加第三张已确认单图，四配色不得传整张拼图；保留其人物处理与配色，旧紧凑大头构图按新胸像比例迁移；第一张仍决定人物特征，第二张仍提供画风。
- 单图与四图逐版核对来源：肤面与硬边肤影必须精确使用所选原作采样，不加皮肤渐变或新高光；完整方案执行single-source-colorways-v1，原作编号、图片路径和采样记录可追溯；全部角色与渐变属于同一source_hd_id，不以“各自都在库内”代替同一原作。默认HD-025/055/016/047；显式指定时核对目录内对应四图。肤色或背景重复允许，不以颜色距离或互异要求改色。旧混搭方案须迁移并记录，真正同源冻结方案不得被独立肤色、背景或art_palette覆盖。
- 所有交付头像（预览/高清、单图及四配色每版）至少一处肉眼清晰的二色连续渐变，普通头像尺寸下能辨认两端颜色、连续过渡和足够面积。头发只是可选位置，也可用衣服或归入衣服角色的服饰色块；对应原作的完整端色、方向与色彩差异均须保留，同一原作多个已采样部位可见时一并保留。全部路线由本地程序按实际可见填色区域分布映射，检查最终RGB及128×128缩略图中的两端覆盖、过渡面积与色彩跨度，不能只凭插值步数通过；编码底稿均不画渐变。区域被遮挡或渐变太弱时，仅可在同一原作已采样的同角色gradient_options中本地重映射，无合用选项则停止，不造色、不跨角色搬端点、不追加生图。单图也使用同一整套原作渐变，不独立设计端色。像素指标不证明角色语义，全部路线仍做一次快速视觉核对。微弱同色漂移、细边亮线、硬切两色、抗锯齿和噪点均不算渐变；皮肤与背景保持既定纯色规则。 已记录的旧同源渐变按 `visible-source-gradients-v2` 补齐原作完整端色，保留原作编号及其余角色色；仅迁移与已知旧目录精确一致的计划，篡改色或来源不符仍拒绝，当前合规冻结方案精确复用。
- `background_plan` 指定铺满四角和外缘的单一纯色不透明底，无背景渐变、纹理、图案或阴影，与头发、服装的大色面明显分离。四配色直接沿用该版同一原作背景且亮度≥150/255，不单换别图背景；不合适则选另一整套方案。两条路线均不计算新底色，不为凑反差改造人物角色色。调用参数含 `--background opaque`；历史参考的背景技法不覆盖新成品规则。
- 统一眼睛画法被记录在 `review_spec.style_lock.eye_style`，所有模式和阶段均一致；批准旧预览的眼白、虹膜层或高光不作保留项，不据此补回眼部细节。
- `line_plan` 记录库内核心主线HEX、来源编号与坐标、用线分类和外轮廓/五官/发内/衣饰处理；每版四类统一该版原作核心色；四版线条几何蒙版相同，线色可随各自原作变化。辅助线色本版仅存档、不绘制，也无启用参数。实际成品核对颜色家族与线条主次；提示词已指定精确HEX不等于生成像素精确通过，不擅自把库外偏色视为新入库颜色。
- 本次参考、主模式、肤发策略、颜色角色、`shadow_plan`、构图和尺寸被记录在 `review_spec.style_lock`；自检不能暗中改选更粗线、更写实或其他模式。
- 四配色的完整同源角色色、线色与渐变继续冻结复用；默认preview low、final high，每版均为1024×1024正方形留白胸像，四配色拼图为2048×2048。旧native尺寸和紧凑构图迁移；仅本次明确其他方形尺寸才传--size。自检不能改变已定的画法与角色色。

本阶段生成一次。不拆成多次收费的草稿/描线/上色调用。失败或超时查原请求结果，不以自检为理由重复提交不确定状态的请求。模型不支持本阶段quality时停止说明，不自动换模型或回退高清。默认交付固定正方形并保留上游原图，不以本地缩图宣称节省生图资源。

## 3. 正方形交付后准备实际对照

按请求尺寸整理为正方形RGB PNG并保留原图。正方形必要时等比缩小；默认square下非方形编码底稿足够大时一次等比适配到技术白色方形底，底边对齐，不裁脸、拉伸或放大，不额外生图。尺寸不足停止。单图透明背景边缘可先合成技术白底，全透明空图拒绝。四配色原始编码底稿必须不透明，不能将透明四配色底稿合成后冒充有效分区。随后以白色编码底完成square适配，再解码并按单图一套或四配色四套计划换色。最终单图和拼图均不得残留编码白底、白边或白色拼缝；背景合成不等于分区或最终颜色已通过。单独运行finalizer可通过--request读取尺寸和背景计划。机器尺寸检查不能证明人物比例或背景纯色合格。单图随后运行下方命令。四配色的review工具按单图检查：对各 `variant_files` 使用对应计划的独立本地请求副本（保留原请求；将 `color_plan`、`background_plan`、`line_plan` 及 `review_spec.style_lock` 的角色色、完整source_colorway来源、肤色来源、背景与渐变替换为对应 `variant_plans` 内容），分别prepare/check；该副本仅供自检，不提交模型。不要把2048拼图传给预期1024单图的尺寸检查，也不要用首版色板判断其余三版。拼图只作同线条几何和整体配色对照；各版另对照其对应原作，而不是仅与025造型参考比较颜色。核对四版共用role-map与line-alpha记录，线色变化允许，轮廓或五官位移不允许。



```bash
python3 "<skill-dir>/scripts/review_avatar.py" prepare \
  --request "<workspace>/outputs/avatar-request-new/generation-request.json" \
  --image "<actual-finalized-image>" \
  --out-dir "<workspace>/outputs/avatar-review-new"
```

输出 `comparison.png`（照片、实际成品、独立风格图）、`thumbnail-128.png` 和待填写的 `review.json`。对照图等比显示，不裁切输入；缩略图用于发现细节丢失，不替换交付图。脚本不修改任何原图，不调用外部服务、不做人脸识别。

`awaiting_visual_review` 只表示材料准备完成。必须用当前环境的看图工具实际查看对照与缩略图，必要时放大照片或成品，不能仅看 JSON、尺寸或提示词就判断画面。

## 4. 逐项视觉自检

填写 `review.json`：实际看过后才把 `visual_review` 四个标记改为 `true` 并写明 `reviewer`。每项对照照片证据、绘画处理与 `do_not_change` 保留边界，填 `observed`、`verdict`；失败还要填 `correction`。保留输入绑定和检查项原有字段不变。

- `observed` 写可见对照，例如“照片两颊饱满、下巴圆；成品下颌明显变窄并形成尖角”，而不是“相似度不错”。
- `pass`：该特征以当前画法清楚体现，或按计划同方向加强，其他辨识关系保持。
- `fail`：关键特征被换形、丢失、被不合理遮住，或生成图借用了参考人物外观、改换年龄/神态、出现结构错误或明显画风漂移。
- `uncertain`：现有画面不足以判断，记录原因，不猜测为通过。原照本身不可见的部位应检查遮挡是否正确，而非要求补出其形状。
- `unreviewed`：尚未实际检查。禁止为省步骤批量把全部条目标为通过。

按本次framing_plan核对头高40%–48%、顶空12%–16%、下巴55%–64%、两侧留白与肩胸可见；不能只检查尺寸。除逐项主特征，还检查表情与姿态、年龄与不对称、配饰与遮挡、头颈/可见手部结构、所选画风、艺术角色色、头发/衣服内1–2处清楚可见的局部二色渐变、暗面细节、构图和缩小后的可读性。`eye_style` 必须实际确认：睁眼为短上眼睑连接向下的单色实心眼形；无包围眼白的杏仁外框、眼白、独立虹膜/瞳孔层、高光或睫毛；闭眼/笑眼允许短弧线，并保留照片眼距、眼宽、倾向、左右差异和神态。若出现禁用细节或统一成同款困倦神态，记录失败。`background_contrast` 必须实际确认背景铺满画布、单一纯色、无渐变/纹理/图案/阴影，且与头发/衣服等大色面有反差；透明底、棋盘格或查看器灰底不能算背景。机器的 `opaque_pixels` 只能证明像素不透明，不能替代纯色及对比的视觉判断。人物结构对照照片。四配色逐版对照其对应原作的完整角色色与采样来源，检查肤色/肤影、背景、发衣、腮红、细节、线色与渐变配对是否一致；任何跨原作拼接、跨角色挪色、无来源新色或为了肤色互异而改色均记录失败。线色跟随对应原作变化可以通过，几何蒙版仍须共用。单图也使用同一原作完整方案，不独立选肤色、背景、线色或渐变；详见 [source-colors.md](source-colors.md)。不能因成品颜色不同于照片判失败。背景不纯、没有清晰人物渐变、两端只在细边出现、仅有微弱同色漂移、硬切两色或在128×128缩略图中渐变消失时，按失败记录，不能称通过。单图和四配色的最终RGB及缩略图指标只校验已知角色蒙版内的渲染可见性，不理解人物语义，仍须依据实际看图记录。

```bash
python3 "<skill-dir>/scripts/review_avatar.py" check \
  --review "<workspace>/outputs/avatar-review-new/review.json" \
  --output "<workspace>/outputs/avatar-review-new/review-result.json"
```

脚本重新检查尺寸/格式、不透明像素和文件哈希，拒绝遗漏检查、缺少观察依据、失败没有修正建议或沿用旧图片评审。它只验证记录与门槛，**不自动理解人物，也不证明人工观察正确**。不输出无依据的相似度百分比，不把自检通过宣称为用户必然认可。

| 状态 | 含义与处理 |
|---|---|
| `passed` | 所有项有依据地通过，且实际看过所需画面；可展示本阶段结果，预览仍须等待用户确认后才能另行生成高清 |
| `needs_revision` | 有失败项或格式尺寸不符，先修明确问题 |
| `needs_manual_review` | 有无法确认项，说明具体限制，不冒称已通过 |
| `awaiting_visual_review` | 尚未完成看图或填写，不能作为已自检完成稿 |

`check` 非通过返回码3，记录错误返回码2。图片、照片、参考或请求改变，旧报告失效，重新 prepare；不能仅改路径继续使用旧观察。

## 5. 仅修失败项，有明确停止条件

本次明确要求review模式时，一次任务最多自动追加 **一轮** 定向编辑，每轮只解决最影响辨识度或画风的1–2项；正常通过时不追加调用。修订保持本次stage、尺寸策略和质量，不用自检修订绕过预览确认或升级高清。请求文件的 `review_spec.max_automatic_corrections` 为0时不能自动追加，不能仅靠运行评审工具提高预算。存在更多独立失败、无法判断或修复所需信息缺失时停止并说明，不自动扩成多轮付费试错。

修订输入以原照片为人物依据，以本次已选参考保持画法，并保留待修插图供局部修改。沿用本次 style_lock 和已通过的特征，只把失败项的 `correction` 加入修订提示词。修正引起脸型或其他部位连带变化时重新核对全部项目；不能用简单几何拉伸照片五官来强行通过，也不借用其他画风的固定倾角或眼睛比例。

每轮保留新版本、实际模型输出、交付图及单独评审记录，禁止覆盖原图。新图按本次尺寸策略交付、prepare 并实际看图复验。修订成功才展示为完成稿；仍失败或无法确认时，展示可供讨论的版本并简明指出未解决项，不能写“已验收通过”。调用状态不明时先查结果；不把超时当成修订预算中的新请求。
