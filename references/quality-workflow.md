# 人物特征、自检与有限修订（显式请求的review模式）

**仅当本次用户要求逐项自检、对照检查或检查并修正时读取并执行。** 在brief设置 `workflow: "review"`，才使用详细提示词与最多一轮修订预算。普通照片转换默认fast，生成、整理尺寸后直接交付，不运行本文件的步骤，也不自动追加调用。旧版默认自检授权不延续到fast模式。

`stage` 与 `workflow` 独立：默认preview请求并交付512×512、quality low；用户通过对话明确确认预览并要求高清后，另行以final请求1024×1024、quality high，交付1000×1000。用户一开始明确要求直接高清时可直接final。自检通过只表示本阶段通过，不代替用户确认，也不自动触发高清；用户只提出修改时保持预览。

review模式保持本次高清参考、平顺线条、五官符号、艺术配色、必需局部渐变、腮红、阴影和交付规范，增加能追溯的自检。全局gen-img仍负责凭据、模型过滤与生图；本Skill仅在明确请求此模式时做画面对照。

## 1. 先把照片事实转成可核对的绘画决定

实际看照片，选择 3–5 项最有辨识力的可见特征。优先覆盖脸型/下颌、眉眼关系或鼻口关系中的可见信息，再结合发型、表情和关键配饰；不能只列“金发、黑衣服、耳环”之类通用标签。被遮挡、过曝或模糊的信息标为不可判断，不猜补；可辨识范围不足时说明限制。

照片只决定结构与神态：脸型、五官关系、发型剪影、衣型和配饰形状需要保留；肤色、发色、衣色与背景色使用参考库或撞色方案，不锁定照片颜色。记录颜色事实时不能让它变成未经用户要求的保色约束。每项分成：照片证据、画成什么、是否加强、不可改变什么。它是相对于这张照片的转译，不是识别人名、推断身份或检索相似人物。例：

```json
{
  "feature_index": 1,
  "photo_evidence": "正面照片里两颊饱满，下颌宽、下巴圆",
  "render_as": "用连续圆弧保留面颊体积和圆下巴，略加强饱满感",
  "emphasis": "emphasize",
  "do_not_change": "不削成尖脸，不缩窄下颌，不把成人画幼态"
}
```

`identity_plan` 覆盖 `identity_features` 的每一项，`feature_index` 从1开始。`emphasis` 只能是 `preserve` 或 `emphasize`，最多两项加强，其余保持。新任务填写明确计划；旧 brief 仍可构建，脚本将已有特征逐项带入，不凭空新增观察。旧 brief 的 `stylization` 继续生效，但调用前须人工核对它与逐项计划没有矛盾。

允许把已有差异画得更清楚：发型更有节奏、圆脸更圆、原有头倾略强、镜框更醒目。禁止将特征反向改造，或同时放大所有五官。眼睛可以按参考概括成小实心眼、短眼睑或必要的眼白瞳点，仍保留间距、走势与神态差异。不能为了“像本人”改成写实脸、3D、固定胶囊眼或另一套画风。

## 2. 调用前核对

检查本次 brief、提示词、`generation-request.json` 三者：

- 每项主特征都有绘画处理，表情含义、视线和头肩关系一致；`stylization` 与逐项保留边界不冲突。
- 第一张只决定人物辨识结构、神态、衣型和配饰形状；第二张提供绘画语言与艺术色彩，不迁移其脸、发型、衣型、配饰或姿势模板。肤色、发色和衣色不必跟照片。经预览升级final时，以 `--approved-preview` 添加第三张已确认图，保留其构图、人物处理与配色；第一张仍决定人物特征，第二张仍提供画风。
- 每张计划1–2处清楚可见的局部二色渐变，写明头发/衣服/背景区域、两端颜色与方向。硬边暗面、两块色、亮线和抗锯齿不算渐变；不把全脸柔焦塑形当作替代。
- 本次参考、主模式、肤发策略、颜色角色、`shadow_plan`、构图和尺寸被记录在 `review_spec.style_lock`；自检不能暗中改选更粗线、更写实或其他模式。
- 默认expressive艺术配色，线条/构图参考与颜色方案可以分别确定；不固定HD-025薄荷背景或肉色肤面。flat等主模式与小尺寸预览都保留局部渐变要求。保存并复用选定的 `art_palette`、`color_roles` 与 `gradient`，升级不重新随机配色。预览默认请求/交付512、quality low，final默认请求1024/交付1000、quality high；用户明确指定的尺寸与质量仍优先，旧版编号独立兼容。

本阶段生成一次。不拆成多次收费的草稿/描线/上色调用。失败或超时查原请求结果，不以自检为理由重复提交不确定状态的请求。模型不支持小尺寸或low时停止说明，不自动改规格、换模型或回退高清；若上游忽略小尺寸返回更大原图，交付缩小预览时注明，不能宣称已节省生图资源。

## 3. 尺寸整理后准备实际对照

先按现有规则用 `finalize_avatar.py` 保留原图、整理交付尺寸。它只检查尺寸和格式，不能代表人物特点合格。再运行：

```bash
python3 "<skill-dir>/scripts/review_avatar.py" prepare \
  --request "<workspace>/outputs/avatar-request-new/generation-request.json" \
  --image "<actual-finalized-image>" \
  --out-dir "<workspace>/outputs/avatar-review-new"
```

输出 `comparison.png`（照片、实际成品、独立风格图）、`thumbnail-128.png` 和待填写的 `review.json`。对照图等比显示，不裁切输入；缩略图用于发现细节丢失，不替换交付图。脚本不修改任何原图，不调用外部服务、不做人脸识别。

`awaiting_visual_review` 只表示材料准备完成。必须用当前环境的看图工具实际查看对照与缩略图，必要时放大照片或成品，不能仅看 JSON、尺寸或提示词就判断画面。

## 4. 逐项视觉自检

填写 `review.json`：实际看过后才把 `visual_review` 四个标记改为 `true` 并写明 `reviewer`。每项对照照片证据、绘画处理与 `do_not_change` 保留边界，填 `observed`、`verdict`；失败还要填 `correction`。保留输入绑定和检查项原有字段不变。

- `observed` 写可见对照，例如“照片两颊饱满、下巴圆；成品下颌明显变窄并形成尖角”，而不是“相似度不错”。
- `pass`：该特征以当前画法清楚体现，或按计划同方向加强，其他辨识关系保持。
- `fail`：关键特征被换形、丢失、被不合理遮住，或生成图借用了参考人物外观、改换年龄/神态、出现结构错误或明显画风漂移。
- `uncertain`：现有画面不足以判断，记录原因，不猜测为通过。原照本身不可见的部位应检查遮挡是否正确，而非要求补出其形状。
- `unreviewed`：尚未实际检查。禁止为省步骤批量把全部条目标为通过。

除逐项主特征，还检查表情与姿态、年龄与不对称、配饰与遮挡、头颈/可见手部结构、所选画风、艺术角色色、1–2处清楚可见的局部二色渐变、暗面细节、构图和缩小后的可读性。人物结构对照照片，色彩对照本次参考/撞色方案，不能因肤发衣色不同于照片判失败。完全没有可见渐变、只用硬边两色冒充或渐变范围被限制到不可辨认时，按画风失败记录。

```bash
python3 "<skill-dir>/scripts/review_avatar.py" check \
  --review "<workspace>/outputs/avatar-review-new/review.json" \
  --output "<workspace>/outputs/avatar-review-new/review-result.json"
```

脚本重新检查尺寸/格式和文件哈希，拒绝遗漏检查、缺少观察依据、失败没有修正建议或沿用旧图片评审。它只验证记录与门槛，**不自动理解人物，也不证明人工观察正确**。不输出无依据的相似度百分比，不把自检通过宣称为用户必然认可。

| 状态 | 含义与处理 |
|---|---|
| `passed` | 所有项有依据地通过，且实际看过所需画面；可展示本阶段结果，预览仍须等待用户确认后才能另行生成高清 |
| `needs_revision` | 有失败项或格式尺寸不符，先修明确问题 |
| `needs_manual_review` | 有无法确认项，说明具体限制，不冒称已通过 |
| `awaiting_visual_review` | 尚未完成看图或填写，不能作为已自检完成稿 |

`check` 非通过返回码3，记录错误返回码2。图片、照片、参考或请求改变，旧报告失效，重新 prepare；不能仅改路径继续使用旧观察。

## 5. 仅修失败项，有明确停止条件

本次明确要求review模式时，一次任务最多自动追加 **一轮** 定向编辑，每轮只解决最影响辨识度或画风的1–2项；正常通过时不追加调用。修订保持本次stage、尺寸和质量，不用自检修订绕过预览确认或升级高清。请求文件的 `review_spec.max_automatic_corrections` 为0时不能自动追加，不能仅靠运行评审工具提高预算。存在更多独立失败、无法判断或修复所需信息缺失时停止并说明，不自动扩成多轮付费试错。

修订输入以原照片为人物依据，以本次已选参考保持画法，并保留待修插图供局部修改。沿用本次 style_lock 和已通过的特征，只把失败项的 `correction` 加入修订提示词。修正引起脸型或其他部位连带变化时重新核对全部项目；不能用简单几何拉伸照片五官来强行通过，也不借用其他画风的固定倾角或眼睛比例。

每轮保留新版本、实际模型输出、交付图及单独评审记录，禁止覆盖原图。新图重新整理尺寸、prepare 并实际看图复验。修订成功才展示为完成稿；仍失败或无法确认时，展示可供讨论的版本并简明指出未解决项，不能写“已验收通过”。调用状态不明时先查结果；不把超时当成修订预算中的新请求。

最终以本阶段实际头像为主，不默认把内部对照拼版当成交付头像。预览通常展示真实512图，简短注明“预览版，确认后可生成高清版”，随后结束本轮；收到用户明确确认并要求高清后才另行生成。final通常展示真实1000成品；未通过时加一句具体限制。用户明确指定其他尺寸时按实际规格说明。用户主动要求审查过程时再提供逐项记录。
