# 人物对照与详细自检

普通fast只生成一次，完成后实际看照片、成品、风格参考并快速核对。**用户明确要求逐项自检或检查并修正时**，设置`workflow: review`并使用下述记录，不把普通出图扩成多轮收费试错。

`stage`与`workflow`独立：默认preview/low；明确确认并要求高清后才另行final/high。用户一开始明确要求直接高清可直接final。每阶段仍只有一张编码底稿，本地完成单图或四配色，预览/高清均遵守当前70套完整同源配色、符号五官、干净肤影腮红、细线衣褶、不透明单色底与贴底。

## 把事实与计划分开

照片直传路线的保留要求不是主模型已经观察的证据。手写观察路线应覆盖3–5项真实可见特征，至少包含脸型/下颌或五官关系，并说明表情、视线与姿态。必要时最多加强1–2项，其余保留；不凭空写特征。

每项`identity_plan`写照片证据`photo_evidence`、绘画处理`render_as`、保留边界`do_not_change`及`emphasis`。逐项计划不能覆盖当前[五官/衣褶](style-language.md)、[发型用线](line-design-guide.md)或用户明确指令。

## 准备真实对照

```bash
python3 "<skill-dir>/scripts/review_avatar.py" prepare   --request "<output>/request/generation-request.json"   --image "<actual-finalized-image>"   --out-dir "<output>/review"
```

输出照片/成品/独立参考的等比对照、128像素缩略图和待填写`review.json`。`awaiting_visual_review`只代表材料已准备，必须用看图工具实际查看。四配色逐版按各自`variant_plans`准备本地检查副本，保留原请求；不能把2048拼图传给1024单图检查，不能用第一版配色判其余三版。

## 观察顺序

1. 身份、脸型、发型大剪影、神态、头肩及原照关键比例是否保留；适度加强是否改变身份或年龄。
2. 留白胸像、完整肩肘腕、真实遮挡和衣着连续是否合理；每版衣服/身体是否贴最后一行。尺寸正确不等于比例合格。
3. 实心眼形是否沿用该版主线色且可读；眼距开合是否保留；嘴宽开口是否符号化又有特征，露齿/不露齿是否遵命。
4. 下颌颈影是否方向合理；腮红是否使用本套角色并轻淡、无颗粒；脸缘是否无故断开。
5. 外套/内搭、领袖、肩带、纹样、首饰和道具是否独立且连接正确；衣褶是否细线，是否有禁用粗填充影或假关节。
6. 每版肤面、肤影、背景、发衣、腮红、线色、细节及人物渐变是否同一TS来源；渐变仅在记录角色可见，背景是否完全不透明单色；四版是否同几何。
7. 128像素下五官、必要装饰和渐变是否仍可读。反光、高光、噪点或细边漂移不能冒充渐变。

没有相应部件不要求凭空补画。看不清的局部放大一次；仍不能确认就写不确定。像素校验只证明覆盖的编码、色值和记录，不证明人体、相似度或画风。

## 填写与校验

实际看过后才填写`visual_review`和`reviewer`。每项写具体可见观察`observed`与`verdict`，失败附`correction`，保留输入哈希和原字段。`pass`表示本项有依据通过；`fail`表示丢失、换形、结构或画风错误；`uncertain`记录无法判断原因；`unreviewed`不能当通过。禁止批量无依据标记全部通过。

```bash
python3 "<skill-dir>/scripts/review_avatar.py" check   --review "<output>/review/review.json"   --output "<output>/review/review-result.json"
```

`passed`可展示本阶段结果，但仍不代替用户确认；`needs_revision`指出待修；`needs_manual_review`说明限制；`awaiting_visual_review`未完成看图。脚本只校验文件、格式、哈希和记录门槛，不自动理解人物，不输出无依据相似度百分比。照片/图/请求变更使旧报告失效。

## 有限修订

fast预算为0；明确review最多一轮定向修订，只有记录允许且已明确提出检查并修正时使用。每次只修最影响识别或画风的1–2项，保持已通过内容、冻结配色、阶段和质量。多项独立失败或信息不足时停止说明，不自动扩成多轮。执行器本身一次只提交一张底稿。

修订以原照片为人物依据，当前模板维持画法，并保留待改插图供定位。身份或衣型偏离时重新参照原照，不在错误图上叠补。所有新版本与评审分开保存，不覆盖原图。修订连带改变其他部位时重新核对；仍失败不写“已验收”。未知请求状态先查记录，不作为新修订请求重发。

最终展示实际成品绝对路径，标明预览；选已有版不生成，明确高清后才另发final。案例适用边界见[confirmed-corrections.md](confirmed-corrections.md)。
